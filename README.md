# 硕士组会 PPT Skill

用于讨论、制作和修改科研进展、论文分享及混合汇报 PPT。

- 讨论时只给方案，明确要求制作时才生成文件；局部修改保留其他已确认内容。
- 根据听众、时长和页数组织主线，先逐页设计理解目标、关键关系、证据和读图顺序。
- 默认学习随 skill 提供的老师项目稿；结合代表页学习问题组织、技术讲解和视觉风格，按内容选择布局。
- 对实际页面完成理解、视觉与可编辑性验收，修正问题后交付。
- 完整制作默认只交付可编辑 PPTX 和独立逐页 Word 讲稿。
- 中间文件只保留制作、检查与续改必要的内容，不额外交付过程报告。

## 安装

把仓库中的 `skills/group-meeting-ppt` 整个文件夹复制到个人 skills 目录，例如 `~/.codex/skills/group-meeting-ppt`。如果已设置 `CODEX_HOME`，使用对应的 `skills` 目录。已经安装时，不要盲目覆盖自己修改过的版本。

也可把本仓库中 `skills/group-meeting-ppt` 的 GitHub 链接交给 Codex，要求使用 skill-installer 安装。

## 调用

```text
使用 $group-meeting-ppt，按附件制作硕士组会 PPT，汇报15分钟，共10页，直接完成。
```

也可以说“先讨论思路”“先审大纲”或“只修改第3页”。提供本次真实内容材料，特殊听众、时长、页数和模板要求在消息中说明。显式要求优先于默认规则。

## 目录

```text
skills/group-meeting-ppt/
  SKILL.md                      唯一核心规则
  agents/openai.yaml            调用元数据
  references/teacher-style.md   老师稿风格和版式分析
  references/teaching-method.md 内容组织与逐页讲解方法
  references/quality-check.md   内部验收明细
  assets/teacher-reference.pptx 原始参考报告
  assets/reference-pages/      十三张代表页
  assets/reference-overviews/  四张总览
```

核心规则只维护一套。本机在已安装的 `SKILL.md` 修改后，同步到仓库发布副本；下载者将仓库中的 skill 安装到自己的技能目录。参考分析与验收明细只补充核心规则，无须再维护一套 AGENTS 规则。

参考素材来自用户提供的学术报告，原有署名见 PPT。它们用于研究内容组织和视觉表达；原稿中的身份、标识、数据与研究结论不自动属于新汇报。

PPTX 和 DOCX 的实际制作、渲染及可编辑性检查，需要运行环境具备相应工具；本 skill 提供工作规则和参考，不包含 PowerPoint/Word 运行时。

## 版本与后续维护

同一个仓库持续更新，不复制多套 skill，也不为每次修改新建仓库。

| 版本 | 内容 |
| --- | --- |
| v1.0.0 | 最初上传的精简版，保留作历史参考 |
| v1.1.0 | 当前详细恢复版：恢复老师模板分析、逐页讲解设计和实际页面验收，保留 PPTX + 独立 Word 讲稿的默认交付 |

- 日常小修改：核对改动后提交一次，提交说明写清解决的问题，GitHub 会保留修改历史。
- 阶段版本：验证实际制作效果、达到一个满意阶段时，再创建版本标签，如 v1.2.0。后续纠正小问题可用 v1.1.1。
- main 分支用于持续更新；需要固定使用某版时，按对应标签安装或下载整个 skill 文件夹，不只下载 SKILL.md。
- 回退时，从选定标签恢复需要的文件并新建一次恢复提交，保留后续历史；不要删除历史或强制覆盖分支。
- 已安装的本机 skill 不会因 GitHub 更新而自动变化；发布或安装更新时核对并同步，避免覆盖尚未保存的本地修改。

以后可以直接对 Codex 说：

```text
修改 $group-meeting-ppt：____。
同步本机 skill、桌面指导文档和仓库副本；检查后提交并上传 GitHub。
本次是普通更新，先不打新版本标签。
```

需要保存阶段版本时补充“这次打一个 v1.2.0 标签”。需要回退时说明标签和要恢复的范围。
